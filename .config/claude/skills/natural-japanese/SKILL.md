# 自然な日本語を書く

Claude が直接日本語を書くと、直訳が紛れ込む。英語の単語に対応する日本語の単語を、日本語にはない意味で使ってしまうのである。これを避けるため、まず英語で文章を書き、Gemini API で日本語に翻訳する。翻訳後、Claude は結果を英語と照合し、意味が変わっている箇所を修正してから使用する。

翻訳の指示には、直訳を避けるための原則と CLAUDE.md の「自然言語生成」セクションだけが含まれる。単語のリストはないため、モデルが更新されてもメンテナンスするものは何もない。

## 手順

### 1. 英語で書く

伝えたい内容を英語で書き、scratchpad に `.txt` ファイルとして保存する。

- 識別子、コード、数値、URL、メンション、Markdown や Slack の記法、英語のまま残す名前は、実際に出力する表記そのままに書く。
- 英語に対応する表現がない日本独自の表現は、英語の下書きの中に日本語のまま書く。例えば、挨拶、依頼や結びの定型句、相手に応じた敬語、読み手への配慮を示す前置きなどである。翻訳ではこれらがそのまま残る。
- 複数の文章 (PR の title と description など) を書く場合は、それぞれ別のファイルに分ける。
- 既存の文書を更新する場合は、追加または変更する段落だけを書く。
- コードのコメントの場合は、コメント記号 (`//`、`#` など) や先頭のインデントを除いた本文だけを書く。1 回の変更で複数のコメントを追加する場合は、1 つのファイル内で空行で区切る。最終稿をソースコードに反映する際に、コメント記号とインデントを戻す。

### 2. Gemini で翻訳する

```bash
~/.claude/skills/natural-japanese/scripts/translate.sh <英語.txt> <日本語.txt> <です・ます|である>
```

文体は出力先に合わせる。人向けの文章 (メッセージ、PR、レビューへの返信) には「です・ます」、文書やコードのコメントには「である」を使う。既存の文書を更新する場合は、その文書の文体に合わせる。

API キーは環境変数 `GEMINI_API_KEY` から読み込まれる。設定されていない場合は、`NATURALIZE_ENVCHAIN_NAMESPACE` に設定された envchain の名前空間から読み込まれる。モデルは `NATURALIZE_MODEL` で変更できる。

API がエラーを返した場合は、エラーの内容をユーザーに伝え、翻訳せずに文章を書いてよいか確認する。ユーザーに伝えずに翻訳をスキップしてはならない。

### 3. 英語と照合する

翻訳後は必ずこの確認を行う。英語と翻訳結果を照合し、以下の点だけを修正する。それ以外は翻訳されたままにする。

- 事実、数値、日付、識別子、限定や範囲、否定、時制、誰が何をするか、あるいは依頼か報告かが変わっている箇所
- 英語のまま残すべきなのにカタカナになっている名前。英語に戻す。
- 相手に対する丁寧さの度合いが変わっている箇所

修正した文章を最終稿としてファイルに書き出す。修正する箇所がなければ、翻訳結果をそのまま最終稿とする。

### 4. 承認する

```bash
~/.claude/skills/natural-japanese/scripts/finalize.sh <英語.txt> <日本語.txt> <最終稿.txt>
```

finalize.sh は、日本語ファイルが英語ファイルに対する translate.sh の出力であることを確認し、最終稿を承認済みとして記録する。

natural-japanese-gate plugin の hook は、承認されていない日本語を含む書き込みや送信をブロックする。対象は git で管理されているファイル (文書は全文、コードはコメントのみ)、commit message、gh で作成する PR や issue の本文、Artifact、MCP を通じた外部サービスへの書き込みである。commit message と PR の本文は、変数を使わない絶対パスのファイルとして渡す。

### 5. 報告して書き込む

書き込む前に、照合で修正した箇所 (翻訳 / 修正後) と最終稿を簡潔に示す。修正した箇所がなければ、「照合で直した箇所なし」と書く。

投稿やファイルへの書き込みには、ステップ 4 で承認された最終稿を使う。書き込む前にユーザーに確認するかどうかは、この skill ではなく通常の判断に従う。

## やり直すタイミング

文を追加したり、段落全体を書き直したり、ユーザーやレビュアーのフィードバックを受けて内容を変更したりした場合は、ステップ 1 からやり直す。

誤字の修正や、数値・URL の差し替えだけを行った場合は、ステップ 1 から 3 をスキップし、次のコマンドで再承認する。

```bash
~/.claude/skills/natural-japanese/scripts/finalize.sh --amend <承認済みの最終稿> <修正後>
```

承認済みの最終稿を変更せずにそのまま書き込む場合は、やり直さない。同じ文章を別の場所に載せる場合や、投稿に失敗した後に再送する場合も同様である。
