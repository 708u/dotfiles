# 自然な日本語への変換

Gemini API で文章を自然な日本語へ書き換え、意味が変わった箇所を Claude が差し替えてから最終稿として使う。

## 手順

### 1. 最終稿をファイルに書き出す

外部に出す文章やリポジトリに書き込む文章を scratchpad の `.txt` に書き出す。Slack や Markdown の記法、メンション、URL、コードブロックは書き込む形のまま含める。

複数の文章を書き込むとき (PR の title と description など) は、文章ごとにファイルを分ける。

既存の文書を更新するときは、追加・変更した段落だけを書き出す。

コードコメントは、コメント記号 (`//`、`#` など) と行頭のインデントを除いた本文を書き出す。1 つの変更で複数のコメントを書いたときは、コメントごとに空行で区切って 1 つのファイルにまとめる。最終稿をソースに戻すときに、コメント記号とインデントを付け直す。

### 2. Gemini で書き換える

```bash
~/.claude/skills/natural-japanese/scripts/naturalize.sh <最終稿.txt> <書き換え後.txt>
```

標準出力に原文との差分、標準エラーにトークン数が出力される。API キーは環境変数 `GEMINI_API_KEY` から読み込む。未設定のときは、`NATURALIZE_ENVCHAIN_NAMESPACE` に設定した envchain の namespace から読み込む。モデルは `NATURALIZE_MODEL` で変更できる。

API がエラーを返したときは、エラーの内容をユーザーに伝え、変換しないまま書き込んでよいかを確認する。ユーザーに伝えずに変換を省いてはならない。

### 3. 意味が変わった箇所を探す

差分の各行を原文と比べ、次のいずれかに該当するものを意味が変わった箇所とする。

- 事実、数値、日付、固有名詞、識別子が変わった
- 情報が追加・削除された。原文に無い修飾語 (「段階的に」「一般」など) が追加された
- 限定や範囲を表す語 (のみ、だけ、以上、未満、すべて、一部) や否定が変わった
- 誰が何をするか、依頼か報告か、予定か完了か、言い切りか推測かが変わった
- 語の言い換えによって指す範囲が変わった (「マシン上」→「環境上」、「分母」→「母数」など)
- 宛先に対する敬語の度合いが変わった
- 記法、メンション、URL、コード、改行の位置が変わった

語の言い換えだけで意味が同じもの (「契機」→「トリガー」など) は差し替えない。

### 4. 意味が変わった箇所を差し替える

差し替えるのは 3 で見つけた箇所のみとし、それ以外は Gemini の出力を残す。

差し替える表現は、原文の意味を保ったうえで前後の文体 (語尾、語彙の硬さ、文の長さ) に合わせる。原文の表現に戻すと前後と文体がずれるときは、意味が同じ別の表現にする。差し替えたあとに文全体を読み、自然な日本語になっていることを確認する。

差し替え後の文章は、Write で scratchpad の `.md` に書き出す。PostToolUse hook で textlint が実行されるため、指摘があれば言い換え、指摘が無くなるまで繰り返す。

### 5. ユーザーに報告して書き込む

書き込む前に、次の 2 点を簡潔に示す。

- 差し替えた箇所の一覧 (原文 / Gemini の出力 / 差し替え後)。差し替えが無ければ「意味の変わった箇所なし」と記載する
- 最終稿

ユーザーが差分の全体を求めたときは、原文と最終稿の差分を示す。

投稿やファイルへの書き込みには 4 で書き出した最終稿を使う。書き込む前にユーザーの確認が必要な場面かどうかは、このスキルではなく通常の判断に従う。

## 再度通す条件

1 つの文章につき 1 回以上通す。通したあとに次の修正を行ったときは、もう一度通す。

- 文を追加した、または段落単位で書き直した
- 本人やレビュアーの指摘を受けて内容を変更した

誤字の修正や、数値・URL の差し替えだけであれば通し直さない。

このスキルで整えた最終稿を変えずに書き込むときも通し直さない。同じ文章を別の場所に出すときや、投稿の失敗で再送するときも同じとする。
